## 4. Portable checks for the two-hour bench window

These are proposed, read-only host checks, not quotations or procedures with 2005-book validation. Keep tools pinned to the deployed OS. Check timestamps against measured NCCL and per-rail RDMA runs. Do not make any host TCP result a fabric PASS.

1. [inference] **Keep records of interface/link events and host-device state** before and after the run. Use `ip -s -d link show`, `ip monitor link` during the run, and `ethtool <interface>` where supported. Keep interface identity, link state/speed, counters, and event timestamps; check changes against benchmark stalls. Use RDMA-specific `ibstat`/`rdma link` separately for each HCA/port. Ethernet interface state is not a substitute for RDMA port state. [ip-link](https://man7.org/linux/man-pages/man8/ip-link.8.html) [ethtool](https://man7.org/linux/man-pages/man8/ethtool.8.html) [NCCL troubleshooting](https://docs.nvidia.com/deeplearning/nccl/archives/nccl_2312/user-guide/docs/troubleshooting/networking_troubleshooting.html)
2. [inference] **Check route and source-interface selection for bootstrap peers.** Use `ip route get <peer-address> from <local-address>`, with the actual source/destination addresses too. An unexpected interface/source or policy-table choice can show the cause of bootstrap/control-plane delay. This check uses kernel IP routing only. It shows nothing about RDMA path selection, switch topology, or fabric adaptive routing. [ip-route](https://man7.org/linux/man-pages/man8/ip-route.8.html)
3. [inference] **Check host receive/softirq pressure as a confound.** Use `mpstat -P ALL 1` and deltas from `/proc/net/softnet_stat` around a representative TCP/bootstrap test. Keep CPU/IRQ affinity and NUMA placement on record if available. The proc format is kernel-version-sensitive; use a version-matched decoder and keep raw samples. Do not show fields as universally named or equivalent to NIC/RDMA drops. [proc(5)](https://man7.org/linux/man-pages/man5/proc.5.html) [mpstat(1)](https://man7.org/linux/man-pages/man1/mpstat.1.html)
4. [inference] **Use a short TCP baseline only when bootstrap/control transport is relevant:** Use matched `iperf3` endpoints on a known path. Keep TCP retransmissions/socket statistics on record, alongside the same-time NCCL sample. A TCP regression with clean RDMA measurements shows a different host/control path. A TCP PASS shows no certification of NCCL payload throughput. Do not use the two-hour window for broad TCP tuning.
