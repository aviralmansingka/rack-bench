## 3. Relevance to rack-bench

[inference] This is unusually relevant background among the existing books. It shows native InfiniBand link, transport, queue-pair, and subnet-management concepts behind RDMA. Use it most for conceptual fault localization. Keep endpoint/transport behavior separate from physical/link and subnet-management issues. Then use current firmware/tool documentation for actual measurements. [Ch. 4](https://www.oreilly.com/library/view/infiniband-network-architecture/0321117654/0321117654_ch04.html) [Ch. 26](https://www.oreilly.com/library/view/infiniband-network-architecture/0321117654/0321117654_ch26.html) [Ch. 27](https://www.oreilly.com/library/view/infiniband-network-architecture/0321117654/0321117654_ch27.html)

[inference] This book shows no evidence for modern GB300/NVL72 performance thresholds. It shows none for current HCA or switch counter semantics, RoCE ECN/PFC configuration, or NCCL algorithm/rail selection. It shows none for SHARP runtime selection or pass criteria.

The existing canon correctly puts operational authority in version-matched NCCL, perftest and vendor manuals. NVLink/NVLink Switch System or MNNVL connectivity can make inter-tray GPU communication possible within an NVL72-class rack. Successful NVLink/MNNVL communication, even across trays, does not by itself show proof. It does not show that tested traffic uses the RDMA/scale-out fabric. It does not show validation of that fabric by tested traffic. ## 4. Portable diagnosis techniques

1. [inference] Use a layer-by-layer fault-isolation model. Check physical port/link and signaling, then link-layer behavior, then transport/QP operation, then subnet management/routing. The chapter topics show support for this model. They do not make a modern rack-bench runbook. [Ch. 26](https://www.oreilly.com/library/view/infiniband-network-architecture/0321117654/0321117654_ch26.html) [Ch. 27](https://www.oreilly.com/library/view/infiniband-network-architecture/0321117654/0321117654_ch27.html) [Ch. 4](https://www.oreilly.com/library/view/infiniband-network-architecture/0321117654/0321117654_ch04.html)
2. [inference] Keep queue-pair state, work requests/completions, ordering, and sequence-number behavior as separate possible endpoint/transport fault domains. Use this separation when you check failed RDMA tests. Check each domain with contemporary verbs/perftest evidence. [Ch. 11](https://www.oreilly.com/library/view/infiniband-network-architecture/0321117654/0321117654_ch11.html) [Ch. 13](https://www.oreilly.com/library/view/infiniband-network-architecture/0321117654/0321117654_ch13.html)
3. [inference] Use subnet-management and subnet-administration concepts. Keep local endpoint health separate from fabric discovery/configuration/addressing/routing questions. A host-only bandwidth result does not show fabric-wide management or topology correctness. [Ch. 27](https://www.oreilly.com/library/view/infiniband-network-architecture/0321117654/0321117654_ch27.html) [Ch. 33](https://www.oreilly.com/library/view/infiniband-network-architecture/0321117654/0321117654_ch33.html)
4. [inference] Use time-bounded correlation with workload results for current physical/link error and performance-counter deltas. Do not use a single snapshot. This is an operational recommendation from current NCCL guidance. It is not a verified prescription or chapter assignment in Shanley. The book chapter location shows no verification. [NCCL troubleshooting](https://docs.nvidia.com/deeplearning/nccl/archives/nccl_2312/user-guide/docs/troubleshooting/networking_troubleshooting.html) [Ch. 25 indexed result](https://www.oreilly.com/library/view/infiniband-network-architecture/0321117654/0321117654_ch25lev1sec2.html)
5. [inference] Keep reliable-connected transport semantics separate from higher-level collective outcomes. Check each rail with current perftest. Then check collective goodput and actual selected transport with NCCL logs. Book concepts alone show no certification for rail balance or measured rack performance. [Ch. 17](https://www.oreilly.com/library/view/infiniband-network-architecture/0321117654/0321117654_ch17.html) [NCCL tests](https://github.com/NVIDIA/nccl-tests)
