# Training research run

Research date: 2026-10-11.

Question: What can a two-hour test check before a tenant starts a 30–90 day training run?

Scope: GB300-class NVL72 rack, 18 trays, Chennai, India.
Audience: rack-bench maintainers, rack operators, and training tenants.

PASS makes measured evidence necessary. A vendor claim or an uptime promise does not make a PASS.
The research uses seven independent category nodes.
Each child makes one sourced category brief.
The orchestrator checks decisive sources and makes the report.

## Files

- `research.md`: node map, state table, and seven short lessons.

- `{neoclouds,hyperscalers,ai-labs,large-companies,clustermax,academia,books}.md`: sourced category briefs.

- `nodes/N01.md` through `nodes/N07.md`: accepted child result records.

- `docs/training-bench-research.md`: distilled bench evidence and design.

- `ORCHESTRATOR-REPORT.md`: checks, verdicts, limits, and handoff paths.

- `oreilly.md`: catalog supplement and reading decisions.

- `oreilly/research.md`: ten independent source nodes and lessons.

- `oreilly/<slug>.md`: ten source notes with access limits and proposed checks.

- `oreilly/nodes/N01.md` through `N10.md`: supplement review records.

## Write boundary

Keep all writes inside this research run directory.
The parent can put the staged reading-list changes into project `docs/training-bench-research.md` after review.
The project copy keeps its position outside this agent's write boundary.
No child makes project-file changes or starts another agent.

## Exclusions

Do not make multi-week reliability claims from a two-hour test.
Do not use the two-hour test in place of GPU, network, storage, internet, inference, or lifecycle category tests.
Do not use destructive hardware fault injection without operator approval.
Do not use a small model as proof of 405B convergence.

## State

All seven category nodes show a done state.
The final map shows seven independent nodes.
The report validator uses one acceptance rule: seven lessons below 50 lines.
The harness sends child completion messages.
The orchestrator does not run repeated pane or session-log checks.
Brief files keep evidence; they do not make workflow recovery automatic.
